# 产品需求文档 (PRD)

## 1. 简介
本文档概述了 **USD/CNY 量化交易概念验证 (POC)** 的产品需求。此 POC 的目标是验证基于 Python 的交易系统的可行性，该系统监控 USD/CNY 汇率，基于简单移动平均线 (SMA) 交叉策略执行自动交易，并在模拟的“纸面交易”环境中跟踪投资组合表现。

---

## 2. 功能需求

### 2.1 市场数据摄取
**FR-01: 实时价格监控**
- 系统必须从公共数据提供商 (例如 Yahoo Finance) 获取当前的 USD/CNY 汇率。
- 默认符号为 `CNY=X`。
- 获取间隔必须是可配置的 (默认: 60 秒)。

**FR-02: 数据处理**
- 系统必须优雅地处理无效或丢失的数据点。
- 系统必须在内存 (或轻量级数据库) 中存储历史价格数据以计算技术指标。

### 2.2 交易策略
**FR-03: 简单移动平均线 (SMA) 交叉**
- 系统必须实施 SMA 交叉策略。
- 输入:
    - `short_window` (默认: 5 个周期)
    - `long_window` (默认: 20 个周期)
- 逻辑:
    - **买入信号:** 当短期 SMA 上穿长期 SMA 时。
    - **卖出信号:** 当短期 SMA 下穿长期 SMA 时。
    - **持有信号:** 其他情况。

**FR-04: 策略配置**
- 策略参数 (窗口) 必须可通过命令行参数进行配置。
- 系统必须验证 `short_window < long_window`。

### 2.3 订单执行 (模拟交易)
**FR-05: 模拟执行**
- 系统必须在不连接真实经纪商的情况下模拟交易执行。
- 交易必须以最后已知价格执行。
- **买入逻辑:** 减少人民币 (CNY) 余额，增加美元 (USD) 余额。
- **卖出逻辑:** 减少美元 (USD) 余额，增加人民币 (CNY) 余额。

**FR-06: 余额验证**
- 系统必须在执行交易前验证资金是否充足。
- 如果资金不足，交易必须被拒绝并记录。

### 2.4 投资组合管理
**FR-07: 余额跟踪**
- 系统必须分别维护美元和人民币的余额。
- 初始余额必须可通过命令行参数配置 (默认: 10,000 CNY, 1,000 USD)。

**FR-08: 权益计算**
- 系统必须在每一步计算以人民币为单位的总权益。
- 公式: `总权益 (CNY) = CNY余额 + (USD余额 * 当前USD/CNY价格)`。

### 2.5 报告和日志记录
**FR-09: 活动日志记录**
- 系统必须将所有主要事件 (价格更新, 信号生成, 交易执行, 错误) 记录到:
    - 控制台 (标准输出)
    - 文件 (`trading.log`)
- 日志格式必须包括时间戳、日志级别和消息。

---

## 3. 非功能需求

### 3.1 性能
**NFR-01: 延迟**
- 系统应在 100 毫秒内 (不包括网络延迟) 处理市场 Tick 并生成信号。

### 3.2 可靠性
**NFR-02: 错误处理**
- 系统不得因瞬时网络错误 (例如 API 超时) 而崩溃。
- 系统必须使用指数退避 (如果适用) 重试失败的数据获取，或跳过该 Tick。

### 3.3 质量保证
**NFR-03: 测试覆盖率**
- 代码库必须对所有核心逻辑模块 (`src/`) 保持 **100% 单元测试覆盖率**。
- 系统必须遵循测试驱动开发 (TDD) 原则。

### 3.4 可用性
**NFR-04: 命令行界面 (CLI)**
- 系统必须提供带有帮助文档 (`--help`) 的用户友好 CLI。
- 参数应包括: 符号 (Symbol), 初始资金 (Initial Capital), 间隔 (Interval)。

---

## 4. 技术约束
- **语言:** Python 3.9+
- **数据提供商:** `yfinance` 库。
- **测试框架:** `pytest`, `pytest-cov`。
- **操作系统:** 跨平台 (Linux/macOS/Windows)。

## 5. 未来范围 (POC 范围之外)
- 用于交易历史的持久数据库 (SQL/NoSQL)。
- 真实经纪商 API 集成。
- 高级策略优化 (回测引擎)。
- 基于 Web 的仪表板/UI。
