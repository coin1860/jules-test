# 用户故事 (User Stories)

## 概述
本文档概述了 USD/CNY 量化交易概念验证 (POC) 的用户故事。主要用户包括 **交易员 (Trader)**、**量化分析师 (Quant)** 和 **系统管理员 (System Administrator)**。

---

## 1. 交易员角色 (Trader Persona)
*作为一个交易员，我希望基于可靠的数据和策略执行交易，以便从 USD/CNY 的价格波动中获利。*

### US-01: 实时市场数据监控
**作为** 交易员，
**我希望** 实时查看当前的 USD/CNY 汇率，
**以便** 我可以做出明智的决策或验证自动化系统的行为。

**验收标准:**
- 系统从 Yahoo Finance 获取最新的 `CNY=X` 价格。
- 价格显示在日志或控制台输出中。
- 价格更新的时间戳可见。

### US-02: 自动交易执行 (模拟交易)
**作为** 交易员，
**我希望** 系统在生成策略信号时自动执行“买入”或“卖出”订单，
**以便** 我不会因为延迟或不在场而错过交易机会。

**验收标准:**
- 当生成“买入”信号时，系统模拟使用可用的人民币 (CNY) 买入美元 (USD)。
- 当生成“卖出”信号时，系统模拟卖出美元 (USD) 换取人民币 (CNY)。
- 如果余额不足，交易将被拒绝。
- 所有交易执行都记录价格、数量和时间戳。

### US-03: 投资组合余额跟踪
**作为** 交易员，
**我希望** 查看我当前持有的美元和人民币余额，以及以人民币计算的总权益，
**以便** 我可以跟踪我的盈亏 (P&L)。

**验收标准:**
- 系统维护美元和人民币余额的分类账。
- 每次交易后，余额正确更新。
- 总权益计算公式为 `CNY余额 + (USD余额 * 当前价格)`。
- 每次交易或市场跳动后记录权益值。

## 2. 量化分析师角色 (Quant Persona)
*作为一个量化分析师，我希望设计和测试交易策略，以便识别有利可图的算法。*

### US-04: 策略定义 (SMA 交叉)
**作为** 量化分析师，
**我希望** 定义一个具有可配置窗口的简单移动平均线 (SMA) 交叉策略，
**以便** 我可以捕捉趋势跟踪机会。

**验收标准:**
- 该策略接受 `short_window` (短周期) 和 `long_window` (长周期) 参数。
- 当短期 SMA 上穿长期 SMA 时生成“买入”信号 (金叉)。
- 当短期 SMA 下穿长期 SMA 时生成“卖出”信号 (死叉)。
- 否则返回“持有”信号。

### US-05: 策略配置
**作为** 量化分析师，
**我希望** 在不更改代码的情况下轻松调整策略参数 (例如窗口大小)，
**以便** 我可以针对不同的市场条件优化策略。

**验收标准:**
- 参数可以通过命令行参数或配置文件传递。
- 系统验证 `short_window < long_window`。

## 3. 系统管理员角色 (System Administrator Persona)
*作为一个系统管理员，我希望确保系统健壮、安全且可审计。*

### US-06: 健壮的错误处理
**作为** 系统管理员，
**我希望** 系统能够优雅地处理网络错误 (例如 Yahoo Finance API 停机)，
**以便** 应用程序不会意外崩溃。

**验收标准:**
- 如果数据提供商失败，系统会重试或记录错误而不会崩溃。
- 关键错误记录有用于调试的堆栈跟踪。

### US-07: 全面的日志记录
**作为** 系统管理员，
**我希望** 详细记录所有系统活动 (Tick, 信号, 交易, 错误)，
**以便** 我可以审计系统行为并诊断问题。

**验收标准:**
- 日志包括时间戳、日志级别 (INFO, ERROR) 和消息详细信息。
- 日志同时写入控制台和文件 (例如 `trading.log`)。

### US-08: 代码质量和可靠性
**作为** 开发人员/管理员，
**我希望** 代码库具有 100% 的测试覆盖率，
**以便** 我可以确信更改不会引入回归。

**验收标准:**
- `pytest` 套件通过所有测试。
- `pytest-cov` 报告显示核心模块 (`src/`) 的覆盖率为 100%。
